Against the proposed rule

Proposed rule: the lowest global qk whose recovery lower bound is at least 0.95, unless macro loss at 262K is more than 0.005 above Keep 1.66. Global 1.88 is the only global-layer arm that passes both (lower bound 0.965, +0.0015). All layers 1.88 also passes, at a higher cost (+0.0043). Global 1.84 misses on recovery (0.918), and Global 2.00 misses on cost (+0.0091). The thresholds were written after the first six arms were seen, so this is a real test only for the arms added later.

Log arms have their own rule, set before the two lower floors ran: recovery lower bound at least 0.90, and macro at 262K at most 0.0015 above Keep 1.66. Floors 32768 and 16384 and every slope from 0.15 pass, including slope 0.4, which is clearly bad on distractor-only NLL. So this rule doesn't separate these arms. Recovery on log arms isn't like-for-like with the others: their full-context and distractor rows run at higher qk than their needle and query rows, which is how floor 16384 exceeds 1.0. Full-context and distractor-only NLL compare more cleanly. About half of floor 32768's macro gain comes from ptb, which is contaminated.

What the arm names mean

qk scales each attention query before its dot product with the keys, so a higher value makes attention sharper. Each layer multiplies queries by qk_mult, and global layers (every 4th layer) also multiply by qk_mult_long_scale.

  • Keep 1.66 is the value the 65K run trained with.
  • Global arms keep the other layers at 1.66 and bring global layers to the named value, with long scale = target / 1.66. For example, 1.88 / 1.66 = 1.133.
  • All layers arms set every layer to the named value.
  • The first sweep's 1.88 and 2.11 were the options first proposed. They resemble the 16K template in #9615: the YaRN factor, and that factor squared, because YaRN scales both queries and keys while the hero scales only queries. From 1.66 that gives 1.89 and 2.15. The second sweep added 1.75 (Snowball's value), 1.84 (the hero's convention from 1.3 at 4K), 2.00 and 2.15.

What MRCR's conditions mean

Each source is a long conversation in which a request is repeated, followed by a final query asking for one of the earlier responses. The gold response is therefore already in the conversation. The model is scored on predicting that response token by token, shown the correct tokens so far. Every condition keeps the worked examples and the final query and scores the same response tokens. Only the middle of the document changes:

ConditionWhat stays in the documentWhat it tells us
Full contextThe whole conversation, typically 130K to 262K tokensThe real test: finding the answer among everything else
Distractor onlyEvery turn except the repeated request's turns, so the answer is goneBaseline with the same kind of long context and no answer
Needle onlyOnly the repeated request's turns, at most about 8K tokensBest case: the answer present with nothing to search through
Query onlyNothing from the conversation, at most about 4K tokensBaseline with no context at all

Distracted gain is distractor only minus full context: what the answer adds inside the long document. Isolated gain is query only minus needle only: what it adds with no distractions. Recovery is distracted gain divided by isolated gain, so 1.0 means the model uses the answer as well in a long document as in a short one.

How to read these

  • These are starting points. Training at 262K will move all of them, and Snowball's recovery rose sharply after it.
  • MRCR here is the native paired eval from #8701, the same one Snowball's long-context work used. Paloma and Uncheatable carry the broader signal.
  • Repeat noise on identical inputs: 4K held-out median 0.00005 per subset, and ptb 0.0027. As a rule of thumb, I would not read macro gaps under about 0.0003.
  • Log arms apply 1 + slope × ln(max(n / floor, 1)) on global layers, with slope 0.1 unless named, where n is the keys in the query's own document. Mean effective qk at MRCR's scored tokens is about 1.84 (floor 65536) and 1.73 (floor 128000).
