## Findings

1. **[P2] Aggregate counts can conceal a missing execution.** `callback_compatibility.py:102-108,128,203-206` executes the composition twice into one collector and only then checks counts >= 2. Identical duplicates are accepted. For any required label/identity, two callbacks in the first execution and none in the second satisfy the gate. The numerical identity checks still pass because the tap is an identity. This is a source-level completeness loophole, not an observed failure of the retained CPU run. Check positive count deltas and complete identities/bytes/errors after each compiled execution's barriers, retain cross-execution and remat byte equality, and record those per-execution observations. Do not impose an exactly-once rule on debug callbacks.

2. **[P2] The prepared worker has no guaranteed 300-second process wall deadline.** `callback_compatibility.py:16-24,228-230` installs its Python SIGALRM after scientific imports; `callback_compatibility_command.json:43-55` directly invokes Python and only describes the wall bound. An in-process Python handler is not a hard deadline during arbitrary native compile/device/effects blocking, and excludes import time. Before dispatch, freeze a supervisor or record an independently enforced scheduler/process watchdog covering the entire worker and terminating its owned process group at the agreed deadline without retry. Root can satisfy this through a separately reviewed dispatch wrapper; the internal alarm remains useful diagnostics.
