## Implemented support worth retaining

The selected raw model is a substantial replacement core, not just a benchmark shim: `models/llama_native.py:96–135,148–308,311–520` has native architecture/sharding, attention, SwiGLU, residual/norm variants, scanned/rematerialized layers, tied/untied heads, token/position forwarding, canonical HF state dictionaries and articulated legacy parameter import. It supports explicit head dimension, norm/bias flags, hybrid/input/QK norms and attention upcasting; those are not all missing simply because the large benchmark uses standard Llama.

PR11 `models/llama_native_lm.py:58–432` supplies the normal LM boundary: named input/activation/loss interfaces around raw parameter leaves; shortened contexts and explicit positions; canonical state serialization; vocabulary resizing; default/linear RoPE; reference/Splash selection; native checkpoint semantic/vocabulary metadata; local HF initialization/export. `main/train_lm.py:116–143,199–218,269–342,385–450,526–543` supplies native mesh mapping, early unsupported-feature guards, FP32 pretrained master loading, complete source vocabulary before model construction, pinned restore selection, full-state resume and the existing export hooks. The checkpoint and HF support is already implemented, not a requirement to rewrite these mechanisms.

PR11 `llama_native_lm.py:224–242` converts the inherited Haliax structured remat policy into native `ScanCheckpointPolicy`. Its public config regression is `tests/test_train_lm.py:224` onward: four layers, nested policy, shortened context, packed segments/sliding window, validation, and exact resumed full state. PR12 `scripts/bench/smoke_llama_native_checkpoint.py:123–176,221–243,287–375` exercises the normal entrypoint and all-rank exact full-state comparison, with finite arrays, step/Adam counters, three completed checkpoints and bounded shard hashing. It is validation code; it does not replace checkpoint implementation.

## Evidence that remains a gate, not another implementation

- The matched benchmark uses its own shared CE (`scripts/bench/bench_llama_native.py:282–336`), fixed canonical initial weights and existing Trainer. Normal train_lm uses adapter `compute_next_token_loss`/the shared named LM loss (`PR11 llama_native_lm.py:361–404`, `models/lm_model.py:319–354`). Both are full Trainer steps, but they are not the same public path or automatic performance evidence for it.
- Existing 107M accepted results and the positive 8aa last-block A/B establish their recorded scope. They do not establish the pending 8aa 1.53B normal timed executable's complete numerical gates. Use the already approved criteria unchanged: FP32 every update/next-parameter tensor relative L2 <=0.005; measured loss vector <=0.001; FP32 first loss/gradients/Adam and all BF16 comparisons retain elementwise atol1e-5/rtol1e-4; exact within-pair initial weights and required physical placements. No additional convergence threshold is invented here.
- Test the extracted/integrated contribution, not only a research snapshot. Existing CPU entrypoint tests, PR12 exact native resume smoke and local HF tests are reusable gates; preserve exact source pins, actual import proof and normal no-hook state checks. A standalone fragment and abstract tracing remain narrower evidence.
- Existing physical resume evidence and any unavailable archived per-rank digests must be reported at their actual evidence boundary. This audit did not re-query jobs or recover additional artifacts.

## Smallest concrete cutover/removal sequence

1. **Assemble the selected contribution source.** Integrate the entrypoint/HF/checkpoint stack, sibling structured-policy fix, known dense-mask fix, checkpoint smoke, and the selected kernel fixes. Resolve overlapping files deliberately. Keep candidate 8aa/full-Trainer results pinned to measured code; revalidate the actual integrated tree with required mechanical/affected/catalog checks. This is integration work, not another benchmark framework.
2. **Close the named public surface deliberately.** Start from actual Llama callers/config presets above. Port needed Llama3/Yarn, decode/cache, loader/serialization and selected options/layouts; explicitly remove abandoned options/callers instead of silently changing their semantics. Preserve the already implemented native standard init/resume/export paths. Decouple canonical Llama configuration from the old model rather than keeping NativeConfig inheriting an old implementation file indefinitely.
3. **Meet the existing acceptance gates on the selected code and public path.** Complete the pending whole-model comparison under current agreed criteria; preserve normal no-hook updates/Adam, exact weights/batch, backend and physical layout provenance. Exercise the public train/eval/init/export/checkpoint paths that will be supported after cutover. Native checkpoint exact resume and source architecture/vocab checks must still hold. No new longer-training/convergence program is required merely to satisfy this audit.
4. **Switch the canonical Llama API once ready.** `model.type: llama`, `LlamaConfig.build/model_type`, default entrypoint factories and experiment presets should all resolve the selected native core. Update call sites together; remove the transitional `llama_native` registry/config layer rather than maintaining two production implementations or adding compatibility aliases by default. Keep stored native checkpoint schema identity stable or intentionally migrate it; registry naming is not a reason to invalidate existing native checkpoints accidentally.
5. **Remove old implementation and unblock dependent families.** Resolve concrete Qwen/Mistral/etc subclasses/imports, then delete obsolete named Llama attention/MLP/decoder/transformer/head implementation and dead dispatch/config branches/tests/docs. Keep only genuinely shared maintained code required by other models, clearly owned outside an obsolete Llama implementation. Verify no production Llama constructors, type assertions or imports still reach the old runtime. If broader Haliax removal is part of the end-state, remove the remaining dependency edges separately and test that claim explicitly.
6. **Keep research history out of the final production design.** The saved merged-9467 guide requires retaining source/notebooks/rejected variants in the logbooks research branch, and independently reviewing each contribution for ongoing maintenance value. The archived matched old implementation, A/B controllers, projection/block replay scripts, temporary wrappers and historical baselines can remain reproducible there after production deletion. Promote useful maintained model/Trainer fixes and focused behavioral regressions; do not keep the old production Llama solely so historical experiments can rerun, and do not promote a one-off runner merely because it produced the final number.

Conclusion: the current work has a native core and implemented normal-training support, but it has not yet replaced the canonical Llama entrypoints. The bounded end-state is one canonical native-backed Llama, the explicitly supported old public behavior preserved or deliberately retired, the old runtime removed without breaking dependent model families, and historical comparison code retained in the research archive.
