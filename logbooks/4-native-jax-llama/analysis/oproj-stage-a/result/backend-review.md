## Installed-source reasoning

1. `jax/_src/callback.py:798–809` explicitly permits the ordinary callback emitter on TPU, then rejects `partitioned=True` unless the platform is CPU/CUDA/ROCm/oneAPI. This is an unconditional platform restriction before callback emission, irrespective of shard-map local shapes. A successful CPU lowering cannot expose it. `debugging.py:108–111` abstract evaluation discards `partitioned`, returns no values, and records a Debug effect; `eval_shape` therefore cannot expose it either.
2. `jax/_src/shard_map.py:110–154` defines inputs as shards and says an empty/default `axis_names` means all mesh axes are manual. `_shmap_checks` at 382–395 resolves that default to all available mesh axes. `_shard_shaped_array` at 865–879 divides the global dimensions by the named mesh-axis sizes. Both lowering paths install `SPMDAxisContext` using the full set of newly manual plus already manual axes: the Shardy path at 996–1002, and the non-Shardy path at 1102–1116. The body therefore receives local avals regardless of whether the surrounding mesh axes were Auto or Explicit.
3. `jax/_src/debugging.py:155–180` selects per-device execution for full-manual `SPMDAxisContext`, using a local/manual callback sharding (Shardy equivalent or MANUAL). It does not branch on `partitioned` to choose this context. Only the outside `ShardingContext` case at 182–195 selects a MAXIMAL/single-device full logical callback. Thus `partitioned=False` **inside full-manual shard_map** does not switch the callback to the outside full-global gather semantics. Its logical argument is already the local shard. The public docstring's False→logical operands/gather description must be interpreted within that context, not as an instruction to reassemble the enclosing global array.
4. `debugging.py:216–219` forwards both the context-selected sharding and the `partitioned` flag for the existing unordered callback. With False, `callback.py:839–861` uses `_emit_tpu_python_callback`. The TPU implementation at 692–762 sends each input to the host with the selected sharding, creates a dummy receive for completion when no callback data results exist, and registers its host callback. `send_to_host`/`receive_from_host` at 605–670 retain the supplied sharding. No second mechanism is required by this source analysis.
5. Full manual matters. The partial-manual/partial-auto branch at `debugging.py:145–171` gathers over remaining auto axes and conditionally selects callbacks. It is not equivalent to the required one-record-per-device behavior. Keep the complete two-axis manual boundary. Do not move the callback outside `shard_map`, remove `ids`, replace local records with host slices, or infer physical original operand buffers from canonical capture-view shards.

For a 2×2 mesh and canonical X shape `[B,H,T,D]`, local X shape remains `[B/2,H/2,T,D]` under `P('data','model',None,None)`. Canonical G `[B,T,E]` under `P('data',None,None)` remains `[B/2,T,E]`; it is replicated over the model axis, but **both model devices must independently report it**. The ids input under `P(('data','model'))` remains a one-element local array, preserving the ordinal association. Global False callbacks continue to receive the enclosing canonical logical values. The existing collector must continue requiring every `(label, ordinal)` and comparing its shape, dtype, and bytes to the corresponding canonical slice.

## Transform and instrumentation implications

- Auto legacy and Explicit native must both be tested. The source supports converting either to a full-manual callback body. However, Explicit inputs also have exact in-spec/type checks (`shard_map.py:284–303`), and `_shmap_checks` requires the supplied mesh to match its enclosing context (`360–372`). The change must retain each variant's existing matching mesh and canonical sharding; changing axis types or adding a nested mismatched mesh is unnecessary.
- Keep `ordered=False` (the current default). The unordered lowering passes the selected sharding. The ordered path (`debugging.py:208–214`) has different token handling and does not pass that sharding there; adding ordering is not this fix and is not a completeness guarantee. Callback order is not part of the evidence identity.
- The Debug effect is registered for lowering, control flow, remat, and custom derivatives (`debugging.py:58–75`). `cond` and `scan` propagate admitted effects. Both `cond` branches are staged; index-zero selection cannot avoid an unsupported TPU lowering in the selected branch. At execution, retain the real dynamic scan index and `lax.cond(index == 0, ...)`, and reject any delivered nonzero index.
- The custom VJP remains the identity: forward returns y and captures canonical X; backward captures actual incoming G and returns `(g, None, None)`. The JAX callback transport flag changes neither that rule nor ordinary output-projection differentiation. Keep the exact patch sites, AST/hash records, and arithmetic. A plain primal-only invocation does not substitute for the differentiated/custom-VJP path.
- `jax.debug.callback` explicitly permits dropped, duplicated, or reordered observations under transformations (`debugging.py:435–445`); source permission for an effect is not exactly-once/completeness proof. Partial evaluation/remat rules at 231–258 intentionally may stage repeated observations. Retain the collector's byte-identical repeated/rematerialized-record check and nonzero counts; do not demand one callback when remat legitimately duplicates it, and do not accept a missing label/device. Preserve `block_until_ready` and `jax.effects_barrier()` before interpreting/finishing records.
- Canonical callback capture can introduce resharding, transfers, and compilation changes. Even successful logical shard-byte capture does not establish original device-buffer tiling or causal equivalence of HLO. Keep the existing scope limitation and HLO retention.
