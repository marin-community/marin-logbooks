# Standard-Llama native generation boundary

At frozen integration `216279e6d8ea9a1c71242509b6b07e946c30d249`, implement the existing **two-method paged contract on `NativeLlamaLmHeadModel`**. There is no model `prefill` method to add: both engine prefill and generation call `decode` (`inference/engine.py:415,695`). Neither native core nor adapter currently implements these APIs.

```python
initial_cache(spec: PageTableSpec, *, dtype) -> ListCache[KvPageCache]
decode(input_ids, kv_cache, batch_info, pos_ids, *, key=None) -> (logits, new_cache)
# tokens/positions: NamedArray[position]; logits: NamedArray[position, Vocab]
```

`PageTableSpec` supplies page count/size. Each layer cache has `[page,slot,2*KVHeads,head_size]` with `(k0,v0,k1,v1,...)` interleaving. `PageBatchInfo` supplies total sequence lengths, page mapping, cumulative query lengths, active sequence count and token destinations. Batch rows are not global sequence slot IDs. Valid tokens occupy a prefix, are contiguous per sequence, and may include multiple sequences in arbitrary slot order (`page_table.py:78-115`, `jit_scheduler.py:201-258,352-389`). Use absolute scheduler positions for RoPE; a packed-buffer offset is not a sequence position.

Reuse the existing engine, PageTable/SequenceTable, KvPageCache/ListCache, sampler and ragged attention. Never convert native parameters to the old Llama model or call its decoder/attention math. Keep cache/named orchestration at the LM boundary and raw core Haliax-free. First prove the small Explicit-mesh cache/ragged bridge on CPU. The native reference-attention `auto_axes` wrapper (`grug/attention/_core.py:288-300`) is the existing pattern for Auto math with pinned explicit output; apply that pattern only around the shared named operation when needed, without host conversions or a global mesh-type change. Its correctness and donation remain tests to perform, not a demonstrated implementation.

Use one packed scheduler stream replicated over data axes, with TP-sharded heads. A decode layout derived from `NativeLlamaSharding(batch_axes=(), same fsdp_axis, same model_axis)` can view tokens as `[1,T]` and hidden states as `[1,T,D]` while preserving existing B/S math. Factor the actual native QKV/head-norm/RoPE and post-attention residual/MLP math into small raw helpers accepting that concrete layout; ordinary forward and decode must call those helpers. Merely adding a unit batch dimension does not override the model's training layout. Existing unbatched activations replicates whole examples across data partitions and has no cache (`llama_native_lm.py:398-411`); it is not a decoder.

Per layer, use `ArrayStacked.get_layer` and its matching ListCache entry. Group Q as `[T,Hkv,Hq/Hkv,D]`, K/V as `[T,Hkv,D]`, update the existing cache, then call `ragged_paged_attention` with the ordinary head scale. Flatten its query heads, cast back to residual compute dtype, and use actual native output projection, block residual/MLP, final norm and tied/untied head. Sequence separation comes entirely from PageBatchInfo, never dense attention over all packed tokens. Preserve scaled RoPE, biases and selected norm semantics through shared native math. The old decoder's layer/cache list traversal exists because its scanned cache path failed aliasing; keep ListCache instead of stacking/concatenating caches (`llama.py:417-467`). This is a model-layer traversal within the one existing engine, not another generation loop.

Concrete first-slice layouts: packed tokens/positions/sequence/page metadata replicated; cache `P(None,None,model,None)`; grouped query `P(None,model,None,None)`; returned logits `P(None,model)`. KV head count must divide the TP size so interleaved K/V pairs stay together. FSDP parameter storage is preserved and gathered for compute. This slice does not implement data-parallel serving or multihost generation. The old engine also has one packed queue/PageTable; with position/seq/page unmapped its logical stream/cache are replicated. Native makes that restriction explicit. Stored data/FSDP parameter sharding is separate from replicated packed-stream compute. Actual old/native physical replication,extra gathers and bytes must be compared before efficiency claims; they were not measured here.

Two caller details need explicit handling. First, engine cache shape sizing/allocation uses `axis_resources`, while runtime decode is ordinary `jax.jit`; NamedArray byte sizing uses the logical mapping (`engine.py:177-184,869-880`, `utils/jax_utils.py:545-599`). The native boundary and sample/eval/server contexts must use the same head mapping and physical layout. Second, engine `compute_dtype` allocates cache; it does not cast the model. Test the intended BF16 model/cache combination and preserve or explicitly reject unsupported mixed/upcast options. Existing cache update casts K/V to page dtype. Paged attention remains causal-only.

`sample_lm.py:73-106,125` has a duplicate loader and old-class assertion. After the separately reviewed shared loader contribution is available, route sampling through it, set the existing explicit-mesh capability before initialization, and admit the native standard-Llama class during transition. Do not copy unpublished loader work. `eval_harness.generate_until` already requires these methods and uses the same engine (`eval_harness.py:786-805,876-880`); no second eval-generation implementation is needed. Server workers re-enter mesh/mapping contexts (`inference/openai.py:208-219,309-320`) and require explicit native setup before server support is claimed.

The shared sampler samples every `model.Vocab` row and has no tokenizer-domain mask (`layers/sampler.py:28-79`). Retained source rows can exceed tokenizer length. Preserve model rows, but define eligible-token handling from explicit tokenizer/padding metadata or reject unsupported mismatched-vocabulary sampling; do not silently truncate the head or classify all source-only rows as padding.

Verification gates:

- On 1CPU and explicit 4CPU data2/model2, verify real bridge/cache values and complete physical layout, K/V pairing, padding non-writes, shape sizing and allocation under the same mapping.
- Compare real native paged logits/cache against independent full causal forward per sequence. Reuse `test_paged_attention.py:268-514`: unequal lengths, reordered/non-dense slots, cached prefixes, chunk/page boundaries, zero-new-token sequences and invalid tails. Add relevant MHA/GQA, tied/untied, BF16/FP32 and long/default/scaled-RoPE cases without a redundant full cross-product.
- Test a real offline tiny loaded native model through existing engine and sample/eval contract: greedy tokens, chunked prompts, stop conditions, multiple generations sharing partial pages, reset/reuse and parent-cache isolation after clone. Existing `test_engine.py` DummyModel coverage does not prove native behavior. Reuse `test_clone_pages.py:22-105` fixtures and preserve donation ownership.
- Add one real offline `LevanterHarnessLM.generate_until` case using existing worker/model/tokenizer setup with two unequal prompts, at least two new greedy tokens and a stop string. It must run actual prefill and incremental calls through the same decode/cache, without mocking engine/model. Pair with a direct-engine case forcing a prompt across prefill chunk/page boundaries. `generate_until` currently hardcodes BF16 cache (`eval_harness.py:867-880`), so use deliberately compatible BF16 native model compute; do not infer FP32 cache from caller dtype.
- Existing paged-attention tests use CPU `1e-4` and TPU `2e-2`; those are kernel-test tolerances, not permission to relax full-Trainer acceptance. Report actual errors. TPU dispatcher catches failures and falls back to reference (`attention.py:1620-1658`); a later separately authorized hardware check must establish the intended kernel actually ran. CPU/abstract success does not establish TPU behavior or performance.
- Run required lint/type/affected safe checks after implementation, and prove shared extraction leaves ordinary forward/loss/gradient, HF and checkpoint behavior intact. No tests or compilation were run in this audit.

Generation completion would close one real standard-Llama gap, not authorize the canonical cutover. When all replacement gates pass, migrate canonical factories/defaults/callers and remove old standard-Llama generation traversal; retain the shared engine/cache infrastructure. Specialized families must retain their own math/masks/cache semantics and have shared dependencies extracted before old-module deletion. Current rejected large-model numerics and legacy full-state conversion remain separate gates. NativeLlama is transitional; this plan does not create a permanent second standard-Llama runtime.
