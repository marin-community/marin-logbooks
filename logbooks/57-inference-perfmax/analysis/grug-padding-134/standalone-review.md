Recommend reviewing [vLLM #134](https://github.com/marin-community/vllm/pull/134) as a small fix for unstable dummy expert IDs. Its standalone GPU benefit is reproduced, and the [missing H100 loading regression now passes](h100-loading.md). The PR remains ready for Romain's review and unmerged. The measured benefit is removal of one source of floating-point variation; model-quality improvement remains unproven.

Tested base: `47a8e415bff17b9376f02d9b92edcc67e962eaee`. Tested candidate: `139b7521151c580f2e524691b53be00127992e64`. The candidate adds two router lines and one regression. It contains none of #133, #132 or the experimental hybrid backend changes. This task made no further product-code changes.

The patch zeros dummy router logits before expert selection. Dummy rows fill fixed-size GPU batches. Their hidden rows and route weights were already zero. Marlin still uses their expert IDs when grouping tokens into expert blocks, so those IDs can change the execution layout for real rows. Real logits and the caller's tensor retain their values.

On one GB200, both installed wheels ran 28 padding comparisons and 16 CUDA graph controls through the explicitly selected FP8 Marlin component. The separate H100 loading check uses the default Triton FP8 MoE backend. No serving benchmark was run. Real inputs, routes and weights stayed fixed in the GB200 comparisons. Only dummy logits changed. All dummy IDs stayed valid. All dummy hidden rows, weights and outputs were zero. Input and packed-weight fingerprints matched between versions.

That control has one real row, three dummy rows and 24 local experts. Each trial ran A, A, B, A, alternating which dummy logits were A and B. Three controls were selected after the first sweep, then repeated 20 times. This selection is exploratory; the full sweep remains in the artifacts.

The broader sweep shows a limited numerical effect. Cases with changed-output differences went from 23/28 to 17/28; cases with same-input differences went from 16/28 to 14/28. Complete same/changed/restored equality after the patch appeared only at 4–8 physical rows with one real row. In all 12 cases with 115–129 real rows, both versions already varied by 0.00006103515625 on identical inputs. These totals include repeat variation and are not counts of corrupted outputs.

In the repeated 16-row, one-real-row control with 96 local experts, changed outputs fell from 20/20 to 5/20 eager and from 20/20 to 12/20 under graph replay. Same-input differences were 4/20 on both versions eager, and 4/20 versus 6/20 under graphs. This control retains numerical variation.

In the repeated 128-row, one-real-row graph control with 24 local experts, changing dummy logits gave a maximum difference of 0.000030517578125 before the patch and 0.0000152587890625 afterward. The patched same-input graph repeats also reached 0.0000152587890625. The harness uses zero routing biases, so dummy selection has tied scores. It checks stable IDs per case but does not record them on every repeat. The cause of the remaining variation was not isolated. These checks do not establish identical full-model token logprobs across prefix-cache reuse and different request batches.
