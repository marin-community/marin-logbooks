# Path B CPU linear merge sweep

The four immutable recipes use the existing `experiments.weight_merging.merge` entrypoint and library bytes. Coefficients of A8a are .25, .49, .51, .75, with A3 as anchor. There is no M50. The library streams one parent shard per reader and computes FP32 arithmetic with one cast to the anchor dtype. Its output uses one tensor per shard (502 shards).

`worker.run` binds the two existing permanent rno2a copies to their verified preservation manifests. It makes a fresh 32-byte output write/read probe, verifies source metadata/ETags, and checks original parent frozen bits before merging. Native `preserve_rows` restores all first-axis rows of the exact 104 frozen fields and rows 128000:128256 of embedding/head from A3 after arithmetic. This restoration is explicit: FP32 averaging itself is not claimed to preserve identical FP32 router values bit-for-bit. All 26 router biases must remain FP32. Parent and output bits are checked against the original v0.1 receipt; special rows also compare actual v0.1 row bytes.

After the unchanged merge CLI completes, the CPU worker reads every output tensor, reports numeric and bit changed-entry fractions versus both parents (including parent-different support), verifies every output object hash, and streams full parent object SHA checks. Only then does it publish `merge-admission.json`. A library merge manifest alone is not this additional admission. The output has merge provenance, not a trained checkpoint event or an FP32-master cast audit.

Each job is 16 CPU / 64 GiB / 40 GiB / 12 hours on cw-rno2a, production priority, with failure/preemption retries both zero. Dependencies and credentials use native EnvironmentSpec with isolated secret files. No model bytes run on the submission host. Nothing deletes or changes either parent. Shrew's measured ~43-minute/20.5-GiB 67B run used a different quantized_ladder script; it is a reference, not a measured runtime for these additional audit passes.

Run a sealed recipe only through the executor-provided `submission(label, code_revision, credentials)`. Offline inspection: `python -m experiments.weight_merging.path_b_sweep.worker --label M25 --code-revision <full commit> --inspect-only`. All subsequent BFCL/native-132/maths evals require actual merge admission and production root/serve checks; parent evaluation results remain controls. No new parent serves are part of this sweep.

The transport successor uses explicit virtual-host S3 addressing, `region_name=auto`, and `when_required` checksum handling in the pinned boto3/botocore 1.41.5 client. The original M25 worker stopped on its first write probe with PathStyleRequestNotAllowed and read no parent tensors. Its corrected initial setup retry has a fresh output namespace; the other three recipes were never submitted. Offline proof exercises botocore's real prepared URL before network dispatch; actual worker write-probe success remains runtime evidence.
